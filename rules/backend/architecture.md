# TypeScript 后端架构

## 入口和依赖

- 启动入口只完成配置校验、日志初始化、数据库连接、依赖装配、路由挂载和优雅停机；业务规则不写在启动文件。
- 配置在启动时一次性解析为强类型对象。缺少必填配置应立即失败；运行代码不散落读取 `process.env`，测试通过显式配置注入。
- 数据库池、Repository、模型客户端和外部服务客户端由组合根创建并注入，不使用隐藏的全局可变单例。
- HTTP server、数据库池、队列和长连接必须响应终止信号：停止接收新请求、等待有界时间内的在途任务、释放资源后退出。

## TypeScript 约束

- 后端 `tsconfig` 开启 `strict`，并根据代码成熟度启用 `noUncheckedIndexedAccess`、`exactOptionalPropertyTypes` 等收紧选项；禁止用关闭检查替代修复类型边界。
- `any` 只允许在有说明的第三方兼容边界，进入领域或持久化前必须转换为 `unknown` 后完成运行时校验。优先使用判别联合、品牌类型和只读类型表达状态与单位。
- DTO、配置、数据库行、外部 SDK 响应和领域对象使用不同 TypeScript 类型；不通过类型断言把未经验证的对象伪装成目标类型。
- 异步函数的错误路径必须可观察；Promise 需要被等待、返回或交给有生命周期管理的任务运行器，禁止无主 Promise。
- `process.env` 只在配置模块读取并校验，业务代码依赖注入后的配置对象；秘密配置缺失时启动失败而不是使用空字符串或开发默认值。
- package manager、Node.js 运行时和依赖版本使用锁文件与 CI 约束；升级运行时或核心依赖时同步检查 API 契约、构建产物和安全公告。

## 请求和业务分层

- Route/Handler 只负责 schema 校验、认证上下文读取、调用用例、状态码和响应 DTO 映射。
- Application Use Case 是一次业务动作的编排入口，负责权限检查、事务边界、领域调用和外部端口调用顺序。
- Domain 层保存领域不变量；需要 I/O 的能力以端口接口表达，由 Infrastructure 实现。
- Repository 接口按领域操作设计，禁止把通用 ORM 查询器暴露给应用层，也不返回 ORM Entity。
- 一个事务内的 Repository 调用必须显式共享同一事务上下文，不能在深层函数偷偷创建第二个连接或独立提交。
- Promise 必须被 `await`、返回或显式托管；禁止未观察的异步任务。后台工作交给具有重试、幂等和关闭协议的 Worker。

## 公用组件目录

- 跨业务复用且与具体领域无关的后端组件统一放在 `backend/src/components/common/`，并以稳定接口提供分页、schema 适配、错误映射、幂等、超时/重试或可观测性等能力。
- 写新 Handler、Use Case、Repository 或 Worker 前，先搜索该目录及现有 feature 实现；已有能力必须复用，不能复制平行版本。
- 只有一个用例使用的逻辑留在用例模块；当需求确认存在两个及以上独立调用方和稳定不变量时，才抽取到公用组件目录。
- 公用组件不能持有业务实体、领域策略、HTTP 请求对象、ORM Entity、数据库连接或模型客户端；依赖通过参数、端口接口或组合根注入。
- 抽取公用组件时同步定义输入/输出类型、错误语义、资源生命周期、并发/幂等行为和测试边界；调用方不得依赖内部实现。

## 异步任务和跨系统一致性

- 数据库写入和必须随之发生的事件记录在同一事务中提交；事务提交后再由 Worker 投递外部系统。
- 外部 API、模型调用和对象存储上传不放在持有行锁的长事务中。确需分阶段时，保存明确状态和幂等键。
- Worker 采用至少一次执行假设；重复消息、进程崩溃和超时重试不得产生重复收藏、重复导入或重复生成结果。
- 任务状态至少区分待处理、处理中、成功、可重试失败和终止失败；认领使用数据库原子更新或 `FOR UPDATE SKIP LOCKED`，并设计租约过期恢复。
- 请求链路统一传播 request id、用户主体和取消/超时信号；日志记录业务标识与阶段，不记录敏感正文。

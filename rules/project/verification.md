# 项目验证基线

## 命令选择

| 改动 | 最低检查 |
| --- | --- |
| React 19 前端行为、样式或配置 | 前端工程的 `lint`、`typecheck`、`test` 和 `build`；交互改动补真实浏览器验收 |
| TypeScript 后端 API、Use Case 或 Worker | 后端工程的 `lint`、`typecheck`、目标单测/集成测试和构建；外部依赖使用隔离 fixture |
| PostgreSQL 18 模型、查询或 Migration | 空库迁移、历史夹具前滚、约束/索引回读、事务并发测试和关键查询计划 |
| AI 网关、工具或生成内容 | schema 成功/失败、超时、限流、恶意输入、工具拒绝、幂等重试、无凭据和错误脱敏路径 |
| 只改项目规则文档 | 检查 Markdown 相对链接、目录路由、文件行数和术语覆盖；无需运行无关代码构建 |

前端和后端工程必须提供可发现的 `lint`、`typecheck`、`test` 和 `build` 脚本；若实际脚本名称不同，在交付记录中写出真实命令。PostgreSQL 验证使用目标 PG18 实例或等价隔离容器，不能以 SQLite 或内存 mock 证明 PG 行为。

## 证据边界

- 依赖安装、静态 mock、类型通过、构建成功只分别证明对应层级；不能证明真实模型、真实音源、云同步、版权授权或生产部署。
- 浏览器手工检查应覆盖加载、空、错误、禁用、导入、收藏、播放切换和窄屏布局；若没有真实浏览器验证，记录未验证范围。
- 数据库交付必须记录迁移版本、schema 查询、关键约束和历史夹具范围；慢查询优化必须保留 `EXPLAIN (ANALYZE, BUFFERS)` 证据。
- 文档交付前检查所有相对链接均指向现有文件，并确认 `AGENTS.md` 只做入口路由、细则已下沉到叶子文件。

# React 19 界面与交互

## 目录和组件职责

- 路由页面负责页面级布局、路由参数和 feature 编排；领域 UI、hooks 和请求逻辑按 feature 聚合；跨领域稳定 UI 放入 `frontend/src/components/common/`。
- 编写页面或 feature 前先检查 `frontend/src/components/common/` 和现有 feature 组件。已有公用组件必须复用；不存在时，只有在需求确实跨两个以上场景或具有稳定复用边界时才新增并存入公用组件目录。
- 新增公用组件前记录其复用场景、输入/输出类型、状态边界和无障碍行为；不要为了“以后可能复用”提前抽取一次性布局。
- 公用组件只承载通用视觉和交互能力，不直接读取业务 API、数据库、模型 SDK 或修改全局业务状态；业务动作通过 props、回调或明确的 feature adapter 注入。
- 叶子组件通过 props、context 或明确的 feature API 获得数据，不直接访问数据库、模型 SDK或散落的网络端点。
- 组件保持纯渲染，派生数据在渲染阶段计算或使用 memo；`useEffect` 只用于与浏览器、网络订阅、音频等外部系统同步，不能用来复制 props 或维护可直接推导的 state。
- 列表使用稳定业务 ID 作为 key。组件卸载或依赖变化时清理定时器、订阅、观察器、动画和 Web Audio 节点。

## React 19 行为边界

- 使用异步 action、transition、Suspense 或 optimistic state 时，必须定义 pending、失败回滚、重复提交和过期响应行为。
- 表单以服务端 schema 为权威，并在客户端提供同等的即时校验；提交后保留字段级错误、焦点定位和可重试输入。
- Error Boundary 只隔离渲染故障；数据请求错误仍通过 feature 状态处理，不能用整页崩溃替代错误界面。
- 懒加载页面为真实包边界，并提供稳定 fallback；不要把首屏关键内容全部推迟到客户端 effect 中获取。

## 界面状态和可访问性

- 查询与变更显式呈现首次加载、后台刷新、空、错误、禁用、成功、待确认和离线状态；toast 只作补充，不能替代页面中的最终状态。
- 所有按钮、链接、菜单和播放器控制支持键盘、可见焦点与可读名称；状态变化通过文本或辅助技术可感知，不能只靠颜色。
- 动画遵守 `prefers-reduced-motion`。音频必须由用户手势启动，并处理 AudioContext 暂停、设备切换、页面隐藏和浏览器不支持。
- 用户或模型提供的文本按纯文本渲染；确需富文本时使用受限语法和成熟 sanitizer，不直接使用 `dangerouslySetInnerHTML`。
- 封面和外部图片有尺寸占位、加载失败和来源策略；未经校验的外部 URL 不直接用于可执行或导航上下文。

## AI 内容交互

- AI 生成内容显示来源、生成状态和审核状态，并提供确认、编辑、重试或放弃入口。
- 流式输出只是临时展示，schema 校验和后端落库成功后才进入权威状态；中断流不得留下半个领域对象。
- 模型失败、拒绝或超时保持用户原始输入，不以空内容或静默 fallback 掩盖。

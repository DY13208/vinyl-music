# 前端数据访问与状态

## API 入口

- 所有请求通过统一 API client 和 feature service 发起，集中处理 base URL、认证、request id、超时、错误 DTO 与 JSON 解析。
- API 类型优先由 OpenAPI/共享 schema 生成；页面不手写重复响应类型，也不直接依赖后端数据库或 ORM 类型。
- 浏览器只携带适合客户端的会话凭据。`VITE_*` 和构建产物内不得出现数据库、模型或服务端密钥。

## 状态分类

- 服务端事实由统一的 server-state 层缓存；组件本地 state 只保存表单草稿、弹窗、排序展示和短生命周期交互。
- 缓存键按资源、用户范围、筛选和分页参数集中定义。登录用户切换或退出时清理受保护缓存，避免跨用户泄漏。
- 写入成功后使用后端返回的规范 DTO 更新缓存或失效后重取；不得只修改局部 UI 并永久跳过权威回读。
- 乐观更新仅用于容易回滚且冲突语义明确的操作。失败必须恢复原快照并给出可执行反馈；高风险或批量写入等待服务端确认。

## 请求竞态和分页

- 搜索、筛选、路由切换和快速翻页使用 `AbortController` 或请求版本丢弃过期响应；较早结果不得覆盖较新输入。
- 组件卸载后不继续更新状态；长请求支持取消，重复点击共享同一请求或由幂等写接口保护。
- 游标分页保留后端返回的 cursor，不在前端推算页边界；筛选或排序变化时重置对应游标链。

## 本地存储

- `localStorage`/IndexedDB 只保存界面偏好、可清理缓存和带版本的离线草稿，不作为账户收藏、权限或生成任务的权威来源。
- 本地内容必须处理版本迁移、解析失败、容量限制和退出清理；敏感正文、Token 和服务端秘密禁止持久化到可被脚本读取的存储。
- 离线写入若被产品采用，必须定义队列状态、冲突策略、幂等键和用户可见同步结果，不能在恢复联网后静默覆盖服务端新数据。

# 鉴权、运行时与操作安全

## 身份和授权

- 认证只建立“请求由谁发起”；每个资源动作仍在后端按用户/账户范围、资源所有权和角色/权限做授权。客户端隐藏按钮不是授权。
- 授权默认拒绝；缺少资源标识、权限服务不可用或上下文不完整时，不以客户端声明或缓存结果放行高风险操作。
- JWT/OIDC 令牌必须验证签名、issuer、audience、过期时间、token type 和密钥来源；不能只 Base64 解码 payload。
- Cookie 会话使用 `HttpOnly`、`Secure`、适当的 `SameSite` 和明确过期/轮换策略；跨站写请求按会话模型启用 CSRF 防护。
- 密码使用成熟的慢哈希算法和随机盐；令牌、API key、模型密钥和数据库密码不进入源码、前端构建、错误响应或普通日志。

## HTTP 和外部输入

- CORS 来源、方法、header 和 credentials 显式 allowlist；空配置不得退化为任意来源。
- body、query、path、上传文件、Webhook 和模型输出都当作不可信输入，执行大小、格式、数量、URL 协议和资源范围校验。
- 外部 URL 请求使用主机 allowlist、禁止内网/metadata 地址、限制重定向、连接超时和响应大小，防止 SSRF。
- CSRF、重放和幂等保护按接口风险设计；Webhook 验签使用原始 body 和 constant-time 比较，并记录事件去重键。

## 错误、日志与观测

- 对外错误使用稳定错误码、可理解消息和 request id；不得返回 SQL、连接串、内部路径、堆栈、令牌或供应商原始敏感信息。
- 结构化日志记录时间、request id、用户范围（脱敏）、资源 ID、动作、结果和耗时；敏感字段采用白名单而不是事后脱敏。
- 指标和 trace 只保留完成诊断所需的标签，避免把完整 prompt、歌词、备注或个人数据放入高基数标签。
- 后台任务、模型调用和外部同步区分可重试失败与终止失败；重试设上限、退避和熔断，避免故障放大。

## 数据和服务保护

- 高风险端点配置按用户/主体和资源限流；限流依赖不可用时明确 fail-open/fail-closed，鉴权、生成和写入端点优先 fail-closed。
- 删除、导出和批量操作显示对象范围、影响和不可逆后果；服务端再次校验范围并记录审计。
- 数据库、队列、模型和对象存储不可用时，接口返回稳定的待重试/待确认状态，不伪造成功或回退到未授权的本地写入。
- 依赖、容器和构建制品使用锁定版本和漏洞检查；供应商 SDK 的权限、数据保留和网络出口在接入时记录。

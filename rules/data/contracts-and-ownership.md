# 数据契约、来源与所有权

## 四层数据类型

- API DTO、领域对象、数据库记录和 AI/外部供应商响应分别定义，通过显式 mapper 转换；任何一层都不能直接复用另一层的内部类型来省略校验。
- 前后端共享的 schema 是字段名称、必填性、枚举、格式和错误结构的唯一契约源；生成类型不得被手工修改，契约变化必须同步生成物和兼容检查。
- 所有输入在进入领域层前完成运行时校验、规范化和字段白名单；未知字段按契约拒绝或忽略，不能悄悄写进 `metadata`。

## 字段语义

- ID、外部来源 ID、slug、条码和展示名称保持不同字段；展示名称不可作为跨表关联或幂等键。
- 时间点、日期、时长、价格、货币、语言和地区均带明确类型或单位；跨 API 时间使用 UTC ISO 8601，展示层再本地化。
- 状态字段定义合法状态与转换，不允许任意字符串；数据库检查约束和领域方法共同保护状态机。
- `null` 表示已知无值，可选字段缺失表示调用方未提供；更新 DTO 明确“保持不变、清空、设置新值”的区别。

## 事实来源和用户边界

- 账户身份和权限来自认证系统；客户端提交的主体、角色和所有权字段只是输入，不能成为授权事实。
- 用户收藏、愿望清单、备注和偏好按用户/账户范围隔离；所有查询、唯一约束、缓存键和事件都保留该范围。
- 专辑、艺术家、版本、曲目、歌词、封面和价格分别记录来源、抓取/生成时间与审核状态；外部来源更新不能覆盖用户自有字段。
- AI 内容保持候选身份，只有经过 schema、来源、权限和必要人工审核后才能成为正式目录投影。

## 删除和审计

- 删除前明确对象的所有者、关联记录、媒体对象、缓存和异步任务处理方式。数据库级联只用于确认属于同一生命周期的子记录。
- 需要审计的修改记录操作者、对象、动作、时间和变更摘要；审计数据不保存秘密或无必要的完整用户内容。
- 软删除仅在确有恢复、审计或法规需求时采用，并明确唯一性、查询过滤、清理周期和最终硬删除流程。

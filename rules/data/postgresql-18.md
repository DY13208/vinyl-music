# PostgreSQL 18 数据模型与查询

## 建模与类型

- 表和列使用稳定的 `snake_case` 业务名称；主键、外键、外部来源 ID 和用户可见 slug 各自承担单一语义，不能混用。
- 时间点使用 `timestamptz` 并以 UTC 写入；日期使用 `date`；持续时间以明确单位的整数列保存。禁止用无时区时间表达真实时间点。
- 价格、金额和比率使用整数最小单位或精确 `numeric`，禁止 `real`/`double precision` 和 PostgreSQL `money` 类型承载业务金额。
- 稳定、可查询、参与约束的业务字段使用强类型列或关系表。`jsonb` 只保存结构确实不稳定、无需核心约束的扩展数据，并要求 schema 版本、大小上限和解析策略。
- 枚举值的演进频繁时优先使用受约束文本或引用表；使用 PostgreSQL enum 前必须确认新增、重命名和回滚策略。
- 大文本、向量、封面文件和音频文件分清存储职责：数据库保存元数据、来源、状态和对象引用；二进制内容进入受控对象存储，除非有已验证的小对象场景。

## 数据不变量

- 非空、取值范围、状态组合、非负数、唯一性和引用完整性使用 `NOT NULL`、`CHECK`、`UNIQUE`、`FOREIGN KEY` 等数据库约束兜底。
- 唯一性不能依赖“先查后插”。需要忽略或更新冲突时使用与业务语义一致的 `INSERT ... ON CONFLICT`，并检查返回结果。
- 外键删除策略必须逐项选择 `RESTRICT`、`CASCADE` 或 `SET NULL`；不允许依赖 ORM 默认值。目录事实、用户收藏、生成来源和审计记录应明确各自保留策略。
- 软删除记录若仍参与唯一性，使用匹配业务语义的部分唯一索引；所有默认查询、统计和后台任务必须一致处理删除状态。
- 多用户数据的唯一约束和索引必须包含用户/账户范围，禁止仅凭对象 ID 假设租户隔离。

## 查询和索引

- 查询只选择需要的列，不使用 `SELECT *`；列表接口限制最大条数，避免无界加载后在 Node.js 内存中过滤、排序或分页。
- 所有 SQL 使用参数绑定或类型安全查询构建器；排序字段、表名等不能绑定的标识符必须来自服务端 allowlist。
- 索引围绕真实查询模式设计：复合索引通常先放等值过滤列，再放范围/排序列，并考虑稳定分页的唯一键。
- 稀疏状态、未删除记录和待处理任务可使用部分索引；包含列只用于有证据的覆盖查询，不为每个字段机械建索引。
- 新增或调整重要查询时，用接近真实规模的数据运行 `EXPLAIN (ANALYZE, BUFFERS)`，核对扫描行数、排序、回表和缓冲命中；不得只因“存在索引”就宣称查询已优化。
- 避免 N+1 查询；通过批量查询、关联加载或领域专用读取模型一次获取需要的数据，同时控制笛卡尔膨胀。
- 深分页使用稳定游标，不以大 offset 扫描；模糊搜索根据实际需求选择规范化列、`pg_trgm` 或全文索引，并限制最短查询长度。

## 事务与并发

- 多个必须同时成功的写入由同一数据库事务包裹，错误必须向上传播并回滚；禁止 catch 后继续提交部分结果。
- 事务保持短小，不在持锁期间调用模型、HTTP 服务、发送邮件或上传对象；跨系统动作使用事务内任务/Outbox 记录后异步执行。
- read-check-write 使用原子 SQL、唯一约束、条件更新或行锁；计数、状态流转和任务认领不能先读到内存再无条件写回。
- 多行加锁按稳定顺序执行，降低死锁；死锁和序列化失败只在整个事务可安全重放时有限重试。
- 默认使用合适的最低隔离级别；需要可重复读或可串行化时必须说明被保护的不变量，并验证重试行为。
- 数据库连接来自有上限的连接池。请求释放、事务结束、超时和应用停机都必须归还连接；连接数预算按进程副本总量核算。

## 权限和诊断

- 应用运行账号使用最小数据库权限，Migration 使用独立受控身份；应用账号不应拥有创建扩展、修改 schema 或超级用户权限。
- 若采用 RLS，策略必须覆盖读取和写入，并用不同用户身份做集成测试；RLS 是数据库防线，不能替代后端资源级授权。
- 慢查询、锁等待、池耗尽和事务重试记录结构化指标；日志不输出完整 SQL 参数中的敏感内容。
